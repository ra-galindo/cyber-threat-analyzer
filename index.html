How This Project Works

Cyber Threat Analyzer is an end-to-end NLP application that classifies cybersecurity-related text such as phishing emails, malicious messages, and suspicious technical alerts using a fine-tuned BERT model. The underlying classifier was developed in my CPSC 556/656 final project at the University of Calgary, and I later extended it into a deployed personal project with a FastAPI backend and a lightweight web frontend.

Problem the Project Solves

Cyber threats often appear in text, such as phishing emails, malicious links, fake support messages, or threat intelligence reports. These are difficult to catch with simple rules because attackers vary wording, tone, and structure. This project focuses on classifying unstructured text into cyber-related threat categories in a way that is fast, practical, and easy to test through a live interface.

Model and Training

The classifier is based on BERT-base-uncased with a sequence-classification head. It was trained on a cyber threat intelligence dataset containing textualized threat examples and labels. A major challenge was class imbalance, so I improved the final model using label consolidation, targeted text augmentation, and class-weighted training. Compared to the baseline, the final model improved from 0.81 to 0.92 F1-score and from 0.77 to 0.94 mean Average Precision, making it much more reliable acrossp underrepresented threat classes.

Deployment Architecture

  • Model layer: fine-tuned BERT classifier hosted on Hugging Face
  • API layer: FastAPI backend that accepts input text and returns predictions
  • UI layer: HTML, CSS, and JavaScript frontend for interactive testing

How to Read the Output

When you submit text, the model returns its top 3 predicted classes along with a confidence score for each one. These percentages represent how strongly the model believes the text matches each category relative to the other classes it was trained on.

  • Top prediction: the model’s best guess for the input text
  • Second and third predictions: alternative classes the model also considered plausible
  • Confidence score: the model’s estimated probability for that class, shown as a percentage

For example, if the model predicts NEED ATTENTION: 87%, no-threat: 11%, and location: 1%, that means it sees the text as most likely belonging to the NEED ATTENTION category, while still assigning a smaller chance to other possibilities. This is useful because cyber threat text can be ambiguous, and showing multiple ranked predictions gives a better sense of uncertainty than a single hard label.

What the Classes Mean

  • NEED ATTENTION: technical or suspicious content that may require investigation, such as URLs, hashes, domains, or other security-relevant indicators
  • SOFTWARE: software-related references or tooling context
  • attack-pattern: descriptions of tactics, techniques, or suspicious behavior patterns
  • identity: references to users, accounts, or identity-related entities
  • location: geographic or environment-related references appearing in security context
  • malware: text indicating malicious software, payloads, or infected artifacts
  • no-threat: benign or non-malicious text
  • threat-actor: references to attacker groups or named adversaries
